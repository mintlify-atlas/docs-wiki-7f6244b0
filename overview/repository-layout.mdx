The Apache Fineract repository is a multi-module Gradle build. At the root sit a few build files, a docker compose matrix that lets you stand up the stack against any supported database, and a tree of subprojects that each own one architectural concern. This page is a flat reference: every directory you see at `ls` time is named and explained, and every Gradle subproject in `settings.gradle` has its own row with the package root and a handful of representative files.

Use it together with the [module graph](/overview/module-graph) page, which adds the dependency arrows on top of this static layout.

## Top-level directories

| Path | What it is |
|------|------------|
| `build.gradle` | Root build script. Plugin versions, common configuration applied to all subprojects. |
| `settings.gradle` | Lists every subproject and dynamically picks up custom modules under `custom/`. |
| `static-weaving.gradle` | EclipseLink static-weaving Gradle plugin configuration shared by JPA modules. |
| `gradle.properties` | Default JVM args, Gradle parallel flags, project version. |
| `gradle/`, `gradlew`, `gradlew.bat` | Wrapper scripts and wrapper jar. |
| `buildSrc/` | Project-local Gradle plugins and conventions (Java toolchain, Spotless, JaCoCo). |
| `config/` | Static configuration shared across modules: `checkstyle/`, `spotbugs/`, `liquibase/` master changelogs, Docker tooling, Eclipse formatter. |
| `custom/` | Customer-specific modules loaded dynamically by `settings.gradle`. Ships with one example: `custom/acme/`. |
| `docker/` | Dockerfiles referenced by the docker-compose stacks. |
| `kubernetes/` | Helm chart and raw manifests for cluster deployment. |
| `scripts/` | Maintenance scripts: Liquibase DDL safety check, JPA scanner, test/feature splitters, signed-commit verification. |
| `CHANGELOG.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `README.md` | Standard ASF project metadata. |
| `LICENSE_*`, `NOTICE_*`, `APACHE_LICENSETEXT.md` | License and notice files for source vs. release. |
| `STATIC_WEAVING.md` | Developer note on EclipseLink static weaving. |
| `lombok.config` | Disables `var`, fixes Lombok with EclipseLink. |
| `renovate.json` | Renovate bot dependency-update rules. |

## Docker compose matrix

Each compose file targets a specific database, broker, or auth mode.

| File | Purpose |
|------|---------|
| `docker-compose.yml` | Default development stack. |
| `docker-compose-mariadb.yml` / `-mariadb-test.yml` | MariaDB persistence; the `-test` variant is tuned for CI. |
| `docker-compose-mysql.yml` / `-mysql-test.yml` | MySQL persistence variants. |
| `docker-compose-postgresql.yml` / `-postgresql-test.yml` | PostgreSQL persistence variants. |
| `docker-compose-postgresql-activemq.yml` / `-postgresql-test-activemq.yml` | PostgreSQL + ActiveMQ external events. |
| `docker-compose-postgresql-kafka.yml` / `-postgresql-kafka-msk.yml` | PostgreSQL + Kafka (self-hosted or AWS MSK). |
| `docker-compose-oauth2-test.yml` | Adds a Keycloak realm for the OAuth2 test suite. |
| `docker-compose-twofactor-test.yml` | Enables the 2FA test profile. |
| `docker-compose-development.yml` | Mounts source for live debugging. |
| `docker-compose-web-app.yml`, `-community-app.yml` | Adds the Mifos X web UI. |
| `docker-compose-custom.yml` | Builds the custom image with `custom/` modules included. |

## Subprojects

The full list comes from `settings.gradle`. Below, each Gradle module has its path, what it owns, the root Java package, and a few files worth opening first.

|---------|---------|--------------|-----------|
| `fineract-core` | Domain primitives, JPA config, JSON command parsing, business date, tenant infra | `org.apache.fineract.infrastructure.core`, `org.apache.fineract.commands` | `FineractContext.java`, `FineractProperties.java`, `CommandWrapperBuilder.java`, `JsonCommand.java`, `BusinessDateApiResource.java` |

### Test harnesses

| Project | Purpose | Key files |
|---------|---------|-----------|
| `integration-tests` | REST-Assured integration tests against a running server | `*Test.java` under `src/test`, `common/` helpers |
| `fineract-e2e-tests-core` | Cucumber step library and test runtime | `*.feature`, step definition classes |

### Customer extensions

The `custom/` directory is special: `settings.gradle` walks it three levels deep (`custom/<company>/<category>/<module>`) and includes any matching Gradle module automatically. The repository ships with `custom/acme/` as a worked example and `custom/docker/` for building a custom image. See [Module graph](/overview/module-graph) for how the loader works.

## Inside a typical subproject

Most Java subprojects follow the same internal layout:

```text
fineract-<module>/
├── build.gradle           # apply plugin: 'java', plugin: 'eclipse'
├── dependencies.gradle    # implementation project(':fineract-core'), ...
└── src/
    ├── main/
    │   ├── java/org/apache/fineract/...
    │   └── resources/
    └── test/
        ├── java/...
        └── resources/
```

<Note>
A handful of subprojects keep dependencies inline in `build.gradle` instead of a separate `dependencies.gradle` — `fineract-war` is the most visible example. Treat the `dependencies.gradle` convention as a soft rule, not a hard one.
</Note>

## Cookbook: finding things fast

<AccordionGroup>
  <Accordion title="Where do API endpoints live?">
    Resource classes are in `fineract-provider/src/main/java/.../api/`, grouped by domain (`loanaccount/api/`, `savings/api/`). Their URL paths are declared with `@Path` annotations on the class.
  </Accordion>
  <Accordion title="Where is the database schema?">
    `fineract-db/src/main/resources/db/changelog/tenant/` for per-tenant tables, `.../default/` for the cross-tenant tenant-list database. Master file: `db.changelog-master.xml`.
  </Accordion>
  <Accordion title="Where do command handlers live?">
    Each portfolio module owns its handlers under `…/handler/`, e.g. `fineract-loan/src/main/java/org/apache/fineract/portfolio/loanaccount/handler/`.
  </Accordion>
  <Accordion title="Where are Quartz jobs declared?">
    The enum `org.apache.fineract.infrastructure.jobs.service.JobName` in `fineract-core` lists every scheduled job. Implementations are scattered across portfolio modules.
  </Accordion>
  <Accordion title="Where is COB defined?">
    `fineract-cob/src/main/java/org/apache/fineract/cob/` contains Spring Batch tasklets. The orchestrator is `LoanCOBManagerService`.
  </Accordion>
  <Accordion title="Where are external event schemas?">
    `fineract-avro-schemas/src/main/avro/` holds `.avsc` files. `fineract-provider` produces them through `ExternalEventProducer` implementations.
  </Accordion>
</AccordionGroup>

## Inside `fineract-provider`

Because `fineract-provider` is the only runnable module, knowing its internal layout pays off when you are tracing endpoints or wiring beans.

| Path inside `fineract-provider/src/main/java/org/apache/fineract` | Contents |
|------------------------------------------------------------------|----------|
| `ServerApplication.java` | Spring Boot main / WAR initializer. |
| `infrastructure/core/boot/` | `FineractWebApplicationConfiguration`, `FineractLiquibaseOnlyApplicationConfiguration`, condition classes. |
| `infrastructure/jersey/` | `JerseyConfig` and the registered API resource list. |
| `infrastructure/jobs/api/` | Scheduler control endpoints. |
| `infrastructure/security/` | Web security configuration, `TenantAwareBasicAuthenticationFilter`, OAuth2 setup. |
| `portfolio/*/api/` | API resource classes for loans, savings, clients, groups, charges, accounting. |
| `batch/api/BatchApiResource.java` | The `/batches` aggregation endpoint. |
| `spm/` | Social Performance Management module (Survey/SPM). |

## Tests, fixtures, and tooling

The repo keeps four parallel test surfaces. Knowing which to use saves time:

| Surface | Module | Style | When to use |
|---------|--------|-------|-------------|
| Unit tests | Inside each subproject's `src/test/java/` | JUnit 5 + Mockito | Pure logic — schedule generation, validators, mappers. |
| Integration tests | `integration-tests/` | REST-Assured against a live server | API contract checks, command-bus end-to-end. |
| Auth mode tests | `oauth2-tests/`, `twofactor-tests/` | REST-Assured plus mode-specific compose stack | Verify behaviour under OAuth2 or 2FA only. |
| E2E scenarios | `fineract-e2e-tests-core/` + `…-runner/` | Cucumber feature files | High-level business scenarios spanning many endpoints. |

Tooling lives in `scripts/`:

| Script | Purpose |
|--------|---------|
| `check-liquibase-ddl-safety.sh` | Flags potentially destructive DDL in pending Liquibase changesets. |
| `jpa-scanner-grouped.sh` | Lists JPA entities grouped by module to spot wiring drift. |
| `split-features.sh`, `split-tests.sh` | Shard Cucumber features and JUnit tests for parallel CI. |
| `verify-signed-commits.sh` | Confirms commit signatures against the contributors file. |

| `config/liquibase/` | Standalone Liquibase tooling configuration. |
| `config/docker/` | Auxiliary Dockerfiles used by some compose stacks. |
| `config/fineractdev-*` | Eclipse formatter and cleanup preferences for contributors. |
| `lombok.config` | Lombok project-wide settings (e.g. disable `var`, set chain default). |
| `static-weaving.gradle` | Shared EclipseLink static weaving configuration; applied by every JPA module. |
