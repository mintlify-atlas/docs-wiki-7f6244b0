Apache Fineract carries a lot of vocabulary — some inherited from its Mifos roots, some specific to microfinance regulation, and some unique to its command-bus architecture. This page is a single alphabetized lookup table for the terms you will encounter when reading code, reviewing PRs, or consuming the REST API. Each row points at the source file where the term is defined or first used so you can jump straight from a word to its implementation.

Use it alongside [Architecture](/overview/architecture), [Module graph](/overview/module-graph), and [Runtime model](/overview/runtime-model). Where a term spans multiple files, the most representative one is cited.

## How to read the table

| Column | What it shows |
|--------|---------------|
| **Term** | The word, acronym, or class name as it appears in code, the docs, or the UI. |
| **Meaning** | A one-or-two-sentence definition. |
| **Source file** | A representative path inside the Fineract repo. Paths are relative to the repository root. |

<Note>
Acronyms are alphabetized by their letters (so "2FA" comes first), and class-style terms are alphabetized by their first significant capital letter.
</Note>

## Glossary

| GLIM | Group Loan Individual Monitoring — a parent loan that aggregates individual member loans for group lending. | `fineract-loan/.../portfolio/loanaccount/data/GLIMContainer.java` |
| GSIM | Group Savings Individual Monitoring — analogous parent/child structure for savings accounts. | `fineract-savings/.../portfolio/savings/data/GSIMContainer.java` |

## Term clusters

Some terms cluster around a single concern. The accordions below group them so you can read a related set in one place.

<AccordionGroup>
  <Accordion title="Command bus terms">
    `CommandWrapper`, `CommandWrapperBuilder`, `CommandSource`, `JsonCommand`, `MakerChecker`, `Idempotency`, `BusinessEvent`, `ExternalEvent`. Together they describe how a write request becomes durable state.
  </Accordion>
  <Accordion title="Accounting terms">
    `GL`, `JournalEntry`, `AccountingBridge`, `Accrual`, `PaymentType`, `ProvisioningCriteria`. The accounting module is mostly read-after-write — it reacts to portfolio events and writes immutable journal rows.
  </Accordion>
  <Accordion title="Tenancy and runtime">
    `TenantStore`, `FineractContext`, `FineractProperties`, `PlatformSecurityContext`, `AppUser`, `BusinessDate`. Every request thread carries a copy of these via `ThreadLocal`.
  </Accordion>
  <Accordion title="Batch and scheduling">
    `Quartz`, `JobName`, `Scheduler`, `COB`, `LoanCOB`, `InlineCOB`, `Tasklet`. The COB engine is Spring Batch; the rest are Quartz cron jobs.
  </Accordion>
  <Accordion title="Lending products">
    `LoanRepaymentSchedule`, `ProgressiveLoan`, `WorkingCapitalLoan`, `GLIM`, `Penny gap`, `NPA`. Lending is the largest functional area of the codebase.
  </Accordion>
  <Accordion title="Savings products">
    `Recurring Deposit`, `ShareAccount`, `GSIM`, `StandingInstruction`. Savings shares many primitives with lending (charges, rates, tax) but its own schedule and posting logic.
  </Accordion>
  <Accordion title="Security and auth">
    `BCrypt`, `OneFA`, `2FA`, `OTP`, `OIDC`. Selectable through Spring profiles and Spring Security configuration.
  </Accordion>
  <Accordion title="Reporting and reference data">
    `ReportingService`, `DataTable`, `CodeValue`, `SqlInjectionPreventer`, `Survey/SPM`. The reporting layer leans heavily on user-extensible tables and ad-hoc SQL — hence the explicit injection preventer.
  </Accordion>
</AccordionGroup>

## Naming conventions in code

Once you internalize the term list above, the codebase becomes navigable largely through naming conventions. Fineract is extremely regular here.

| Suffix | Role |
|--------|------|
| `*ApiResource` | Jersey JAX-RS endpoint class. |
| `*WritePlatformService` | Domain service that executes commands and mutates state. |
| `*WritePlatformServiceJpaRepositoryImpl` | Concrete write service implementation backed by JPA. |
| `*ReadPlatformService` | Domain service that exposes read projections. |
| `*ReadPlatformServiceImpl` | Concrete implementation, usually backed by `JdbcTemplate`. |
| `*CommandHandler` | Thin `@CommandType` bean that wires a command to its write service. |
| `*Repository` | Spring Data JPA repository over an aggregate root. |
| `*Mapper` / `*RowMapper` | Maps a `ResultSet` row to a DTO. |
| `*DataValidator` | Builds `ApiParameterError` lists for input. |
| `*BusinessEvent` | Domain event raised inside a transaction. |
| `*ExternalEvent` | Avro-serializable form of a business event. |
| `*Container` | Aggregating wrapper, often used for GLIM/GSIM parent groupings. |
| `*BusinessStep` | Spring Batch tasklet within a COB job. |

<Info>
The few times this convention is broken (e.g. `JsonCommand` instead of `JsonCommandData`) usually mark code that predates the convention — they are stable surface, just historically named.
</Info>

## REST headers you will see

Several Fineract-specific HTTP headers are baked into the glossary because they show up in code and in client SDKs.

| Header | Meaning | Implemented by |
|--------|---------|----------------|
| `Fineract-Platform-TenantId` | Selects the tenant whose data to operate on. | `TenantAwareBasicAuthenticationFilter` |
| `Authorization` | Standard basic-auth or `Bearer` (OAuth2) token. | Spring Security |
| `Fineract-Platform-OTP` | One-time password when 2FA is enabled. | `TwoFactorAuthenticationFilter` |
| `Idempotency-Key` | Lets the client safely retry a write request. | `IdempotencyKeyResolver` |
| `Command` (query param `?command=`) | Verb dispatcher used by API resources. | `CommandWrapperBuilder` and resource classes |

## Common parameter names in JsonCommand

Write requests carry JSON bodies. Across the codebase the parameter names are deliberately consistent; remembering this list speeds up reading `JsonCommand.stringValueOfParameterNamed("…")` calls.

| Parameter name | Found on |
|----------------|---------|
| `locale`, `dateFormat` | Every body that contains dates or numbers. |
| `externalId` | Any entity that supports a client-supplied id. |
| `clientId`, `groupId`, `officeId`, `staffId` | Entity attachments. |
| `productId` | Loan/savings/share product reference. |
| `principal`, `numberOfRepayments`, `repaymentEvery`, `repaymentFrequencyType` | Loan terms. |
| `interestRatePerPeriod`, `interestType`, `interestCalculationPeriodType` | Interest configuration. |
| `expectedDisbursementDate`, `submittedOnDate`, `transactionDate` | Date inputs. |
| `paymentTypeId`, `accountNumber`, `chequeNumber` | Payment detail. |
| `note` | Free-form audit comment. |

## Mini timeline of the project

Knowing where Fineract comes from explains the leftover vocabulary.

| Era | What happened |
|-----|---------------|
| Mifos (early 2000s) | Original Java microfinance platform from the Grameen Foundation. |
| MifosX (2012) | Rewrite around a REST API and command bus — the direct ancestor of Fineract 1.x. |
| Apache incubation (2016) | Project donated to the ASF; renamed Fineract. |
| Fineract 1.x | Monolithic codebase, single Gradle project. |
| Fineract today | Modularized into ~30 Gradle subprojects, Spring Boot 3, EclipseLink with static weaving, optional progressive loans, external Avro events. |

That history is why you sometimes see `Mifos` references, `MifosX`-style class names, and a mix of newer and older idioms in adjacent files.
