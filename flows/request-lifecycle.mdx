Apache Fineract is a Spring Boot application that combines an embedded servlet container, Spring Security, Jersey (JAX-RS), Spring Data / JPA / EclipseLink, and a custom command dispatcher. To understand any individual feature it helps to know exactly what happens between the TCP connection landing on the container and the JSON response leaving it. This page walks that path end-to-end against the current sources under `fineract-provider/`, `fineract-security/`, and `fineract-core/`.

The trace follows a single write request — `POST /api/v1/loans/123/transactions?command=repayment` — but every step applies to any non-`OPTIONS` request to `/api/**`.

## What we are tracing

| Layer | Class / file |
| --- | --- |
| Boot / container | `ServerApplication` (`fineract-provider/src/main/java/org/apache/fineract/ServerApplication.java`) |
| Jersey config | `JerseyConfig` (`fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/jersey/JerseyConfig.java`) |
| Spring Security filter chain | `SecurityConfig#filterChain` (`fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/config/SecurityConfig.java:122`) |
| Tenant / auth filter | `TenantAwareBasicAuthenticationFilter` (`fineract-security/src/main/java/org/apache/fineract/infrastructure/security/filter/TenantAwareBasicAuthenticationFilter.java`) |
| Idempotency, COB, correlation filters | `IdempotencyStoreFilter`, `LoanCOBApiFilter`, `CorrelationHeaderFilter`, `RequestResponseFilter` |
| JAX-RS resource | `LoanTransactionsApiResource` (`fineract-provider/src/main/java/org/apache/fineract/portfolio/loanaccount/api/LoanTransactionsApiResource.java`) |
| Command dispatcher | `PortfolioCommandSourceWritePlatformServiceImpl` + `SynchronousCommandProcessingService` |
| Domain service | `LoanWritePlatformServiceJpaRepositoryImpl` |
| Persistence | JPA / EclipseLink + JDBC via the tenant `DataSource` |
| Response serialization | `ToApiJsonSerializer` |

## High-level pipeline

<Steps>
  <Step title="Container hands off to Spring DispatcherServlet">
    The embedded servlet container receives the HTTP request and routes anything under `/api` to the JAX-RS servlet declared by `JerseyConfig` (`@ApplicationPath("/api")`, `fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/jersey/JerseyConfig.java:36`). Before Jersey sees the request, the Spring Security filter chain attached to `/api/**` runs in order.
  </Step>
  <Step title="Tenant + basic-auth filter resolves Fineract-Platform-TenantId">
    `TenantAwareBasicAuthenticationFilter` extracts the `Fineract-Platform-TenantId` header, loads the tenant via `AuthTenantDetailsService`, pins it onto `ThreadLocalContextUtil`, then runs the standard `BasicAuthenticationFilter` super-method to authenticate the user (`fineract-security/src/main/java/org/apache/fineract/infrastructure/security/filter/TenantAwareBasicAuthenticationFilter.java:96`).
  </Step>
  <Step title="Correlation, instance-mode, COB, idempotency filters run">
    `SecurityConfig` registers `CorrelationHeaderFilter`, `FineractInstanceModeApiFilter`, `LoanCOBApiFilter`, and `IdempotencyStoreFilter` in that order after the auth filter (`fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/config/SecurityConfig.java:421-435`). For loan paths, `LoanCOBApiFilter` may trigger inline COB before the resource is reached.
  </Step>
  <Step title="Jersey dispatches to the JAX-RS resource">
    Jersey matches `POST /v1/loans/{loanId}/transactions?command=repayment` to `LoanTransactionsApiResource#executeLoanTransaction` (`fineract-provider/src/main/java/org/apache/fineract/portfolio/loanaccount/api/LoanTransactionsApiResource.java:296`), which delegates to `executeTransaction()` at line 550.
  </Step>
  <Step title="Resource builds a CommandWrapper and calls the dispatcher">
    The resource composes a `CommandWrapper` via `CommandWrapperBuilder#loanRepaymentTransaction` (`fineract-core/src/main/java/org/apache/fineract/commands/service/CommandWrapperBuilder.java:1208`) and hands it to `PortfolioCommandSourceWritePlatformServiceImpl#logCommandSource` (line 611 of the resource).
  </Step>
  <Step title="Dispatcher persists CommandSource and calls the @CommandType handler">
    `SynchronousCommandProcessingService#executeCommand` resolves the idempotency key, persists a `CommandSource`, looks up the `@CommandType(entity="LOAN", action="REPAYMENT")` handler (`LoanRepaymentCommandHandler`), and calls it inside a transaction.
  </Step>
  <Step title="Domain service writes via JPA, posts journal entries, emits events">
    `LoanWritePlatformServiceJpaRepositoryImpl#makeLoanRepayment` (`fineract-provider/src/main/java/org/apache/fineract/portfolio/loanaccount/service/LoanWritePlatformServiceJpaRepositoryImpl.java:961`) mutates the aggregate, calls JPA via EclipseLink, posts GL entries, and fires business events.
  </Step>
  <Step title="Response is serialized; transaction commits; webhook hook fires">
    `ToApiJsonSerializer.serializeResult` formats the `CommandProcessingResult` as JSON, the surrounding `@Transactional` commits, and `SynchronousCommandProcessingService#publishHookEvent` is fired (`fineract-core/src/main/java/org/apache/fineract/commands/service/SynchronousCommandProcessingService.java:183-217`).
  </Step>
</Steps>

## Step-by-step notes

### 1 — Container and entrypoint

The application is launched by `ServerApplication#main` (`fineract-provider/src/main/java/org/apache/fineract/ServerApplication.java`). For `bootRun` / executable JAR launches the embedded container (Tomcat by default; can be swapped to Jetty/Undertow via `spring-boot-starter-jetty`) hosts the same Jersey configuration. For traditional WAR deployments, `SpringBootServletInitializer#configure` wires the same `Configuration` source, so the request path described here is identical regardless of how the WAR is hosted.

### 2 — Spring Security filter chain order

`SecurityConfig#filterChain` (`fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/config/SecurityConfig.java:122`) registers filters around the default Spring Security stack via `addFilterBefore` / `addFilterAfter`. The effective order for `/api/**` is:

1. `TenantAwareBasicAuthenticationFilter` — `addFilterBefore(...SecurityContextHolderFilter.class)` (L421)
2. `RequestResponseFilter` — `addFilterAfter(...ExceptionTranslationFilter.class)` (L422)
3. `CorrelationHeaderFilter` — after `RequestResponseFilter` (L423)
4. `FineractInstanceModeApiFilter` — after `CorrelationHeaderFilter` (L424)
5. `LoanCOBApiFilter` — after `FineractInstanceModeApiFilter` (L427)
6. `IdempotencyStoreFilter` — after `LoanCOBApiFilter` (L428)
7. `ProgressiveLoanModelCheckerFilter` — before `LoanCOBApiFilter` (L429)
8. Optional `TwoFactorAuthenticationFilter` — after `CorrelationHeaderFilter` when 2FA enabled (L438)
9. Optional `CallerIpTrackingFilter` (L435)

### 3 — Tenant resolution and authentication

`TenantAwareBasicAuthenticationFilter` (`fineract-security/.../filter/TenantAwareBasicAuthenticationFilter.java:96`) extends Spring's `BasicAuthenticationFilter`. Inside `doFilterInternal` it:

- resets the request-scoped `ThreadLocalContextUtil` (L99),
- short-circuits `OPTIONS` requests (L101–104) for CORS preflight,
- pulls `Fineract-Platform-TenantId` from the header — or the `tenantIdentifier` query param as a fallback (L108–114),
- throws `InvalidTenantIdentifierException` if missing (L116),
- calls `AuthTenantDetailsService#loadTenantById` to look up the tenant in `fineract_tenants.tenants` and resolve its `tenant_server_connections` row (L129),
- pins the tenant and business dates onto the thread (L130–132),
- delegates to the base class `super.doFilterInternal` to validate the `Authorization: Basic ...` header against the tenant-scoped `TenantAwareJpaPlatformUserDetailsService` (L153).

Critically the `finally` block (L161) calls `ThreadLocalContextUtil.reset()` so the worker thread leaves the pool with a clean context.

### 4 — Jersey dispatch and resource binding

`JerseyConfig` (`fineract-provider/src/main/java/org/apache/fineract/infrastructure/core/jersey/JerseyConfig.java`) is a `ResourceConfig` with `@ApplicationPath("/api")`. At `@PostConstruct` it auto-registers every Spring bean annotated with `@Path` or `@Provider` (L55-58), so all JAX-RS resources defined under `fineract-provider/.../api/` become available without explicit registration.

For our trace, `LoanTransactionsApiResource` (`@Path("/v1/loans")`, L87) matches `POST {loanId}/transactions` (L275). Jersey injects the `@PathParam("loanId")`, `@QueryParam("command")` and request body, then invokes `executeLoanTransaction` (L296), which delegates to the package-private `executeTransaction(loanId, null, "repayment", body)` (L550).

### 5 — From resource to command dispatcher

`executeTransaction` builds a `CommandWrapper` using `CommandWrapperBuilder.loanRepaymentTransaction(resolvedLoanId)` (`fineract-core/src/main/java/org/apache/fineract/commands/service/CommandWrapperBuilder.java:1208`) — that method sets `actionName=REPAYMENT`, `entityName=LOAN`, the `loanId`, and an `href` template — and calls `commandsSourceWritePlatformService.logCommandSource(commandRequest)` (resource L611).

`PortfolioCommandSourceWritePlatformServiceImpl.logCommandSource` (`fineract-core/src/main/java/org/apache/fineract/commands/service/PortfolioCommandSourceWritePlatformServiceImpl.java:57`) checks permissions, parses the JSON body into a `JsonCommand`, and delegates to `SynchronousCommandProcessingService.executeCommand` (L77).

### 6 — Synchronous command processing

`SynchronousCommandProcessingService.executeCommand` (`fineract-core/src/main/java/org/apache/fineract/commands/service/SynchronousCommandProcessingService.java:91`) wraps the work in a Resilience4j retry, resolves the idempotency key, and persists an initial `CommandSource` row via `CommandSourceService.saveInitialNewTransaction` (L125). It then resolves the handler with `findCommandHandler(wrapper)` (L138), which in turn calls `CommandHandlerProvider.getHandler("LOAN", "REPAYMENT")` (`fineract-core/src/main/java/org/apache/fineract/commands/provider/CommandHandlerProvider.java:88`) — backed by the registry built in `initializeHandlerRegistry` (L57) from every Spring bean carrying `@CommandType(entity, action)`.

The handler is invoked inside `CommandSourceService.processCommand` (`fineract-core/src/main/java/org/apache/fineract/commands/service/CommandSourceService.java:143`), where the maker-checker check (`isMakerCheckerEnabledForTask`) decides whether to mark the row as `AWAITING_APPROVAL` and throw `RollbackTransactionNotApprovedException` (L158).

### 7 — Handler → domain service → JDBC

`LoanRepaymentCommandHandler.processCommand` (`fineract-loan/src/main/java/org/apache/fineract/portfolio/loanaccount/handler/LoanRepaymentCommandHandler.java:43`) calls `writePlatformService.makeLoanRepayment(LoanTransactionType.REPAYMENT, command.getLoanId(), command, false)`. The implementation in `LoanWritePlatformServiceJpaRepositoryImpl.makeLoanRepayment` (`fineract-provider/.../service/LoanWritePlatformServiceJpaRepositoryImpl.java:961`) loads the aggregate (`loanAssembler.assembleFrom`), runs validators, builds a `LoanTransaction`, lets `loanTransactionProcessingService.processLatestTransaction` (L992) allocate the amount against installments per strategy, saves transactions, calls `journalEntryPoster.postJournalEntriesForLoanTransaction`, and emits `LoanTransactionBusinessEvent`s through `BusinessEventNotifierService`.

All persistence is JPA via EclipseLink against the tenant-scoped `DataSource` resolved earlier; the actual SQL is the standard `SELECT … FOR UPDATE` / `INSERT` / `UPDATE` traffic of EclipseLink against the tenant's MySQL/MariaDB/PostgreSQL.

### 8 — Result persistence, hook fan-out, response

Back in `SynchronousCommandProcessingService.executeCommand` (L182–204), the result is serialized into the `CommandSource.result` column, the row is flipped to `PROCESSED`, and `publishHookEvent(entity, action, command, result)` fires (L217). The JSON returned by `ToApiJsonSerializer.serialize(result)` (resource L612) is the body the client sees.

`TenantAwareBasicAuthenticationFilter.onSuccessfulAuthentication` (L170–181) adds an `X-Notification-Refresh: true|false` header before the response is written.

## What can interrupt the pipeline

The diagram shows the happy path. Several side channels can short-circuit it:

- **Invalid tenant header** — `InvalidTenantIdentifierException` thrown at L116 is caught at L155 and turned into `400 Bad Request` with a `WWW-Authenticate` header. The chain never reaches Jersey.
- **Authentication failure** — `BasicAuthenticationFilter` raises `BadCredentialsException`, mapped to `401` by `BasicAuthenticationEntryPoint` (`SecurityConfig.java:496`).
- **Read-only instance** — `FineractInstanceModeApiFilter` rejects non-GET requests with `InvalidInstanceTypeMethodException`.
- **Loan locked / behind COB** — `LoanCOBApiFilter` calls `helper.executeInlineCob(loanIds)` when `isLoanBehind(...)` is true, or rejects with `409` when the loan is hard-locked (see the dedicated [Inline COB flow](/flows/inline-cob-flow) page).
- **Idempotent replay** — when the resolved idempotency key matches a row in `m_portfolio_command_source` with status `PROCESSED`, `SynchronousCommandProcessingService.exceptionWhenTheRequestAlreadyProcessed` (L238–258) throws `IdempotentCommandProcessSucceedException`, and the stored response body is replayed.
- **Maker-checker** — `CommandSourceService.processCommand` (L148–160) flips the row to `AWAITING_APPROVAL` and throws `RollbackTransactionNotApprovedException`, which the JAX-RS mapper translates to `403`.
